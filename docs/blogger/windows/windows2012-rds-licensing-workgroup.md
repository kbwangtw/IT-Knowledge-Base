# Windows Server 2012 無網域單機安裝遠端桌面服務與授權（摘要）

> **一句話**：沒有網域的單機要讓多人同時遠端桌面，要安裝「遠端桌面工作階段主機」與「遠端桌面授權」兩個角色、啟用授權伺服器、安裝 RDS CAL，再用群組原則指定授權伺服器與授權模式。

## 1. 先認識幾個名詞

| 名詞 | 白話解釋 |
| --- | --- |
| **RDS（遠端桌面服務）** | 讓多人同時遠端登入同一台伺服器 |
| **RD 工作階段主機** | 實際讓使用者登入的角色 |
| **RD 授權** | 管理 RDS CAL 的角色 |
| **RDS CAL** | 每位使用者或每台裝置連線需要的授權，分「每使用者」與「每裝置」 |
| **Open 大量授權** | 企業常見的授權購買方式，安裝時選對應的授權類型 |

## 2. 流程重點

```text
① 新增角色：用「角色型或功能型安裝」（無網域時不能用 RDS 的快速部署精靈）
     勾選 RD 工作階段主機、RD 授權
② 啟用授權伺服器：開啟「遠端桌面授權管理員」→ 啟用伺服器
③ 安裝授權：在授權管理員安裝 RDS CAL（依購買方式選，例如 Open 大量授權）
④ 指定授權：gpedit.msc → 遠端桌面工作階段主機 → 授權
     設定「使用指定的遠端桌面授權伺服器」（填本機）與授權模式（每裝置／每使用者）
```

| 注意事項 | 說明 |
| --- | --- |
| 只是遠端管理 | 系統預設允許 2 個管理連線，**不需要**安裝 RDS 角色與 CAL |
| 無網域只能用「每裝置」CAL 才能被正確追蹤 | 工作群組環境中「每使用者」CAL 不會被授權伺服器追蹤（Microsoft 官方文件已確認，見第 3 節） |
| 寬限期 | 未設定授權時有 120 天寬限期，到期後無法連線 |

## 3. 授權規則（依 Microsoft 官方文件整理，非原文內容）

> 原文網站已消失，以下整理自 Microsoft Learn〈License Remote Desktop Services with Client Access Licenses (CALs)〉，不是原文作者寫的。

### 3-1 每裝置 vs 每使用者

| 比較 | 每裝置（Per Device）CAL | 每使用者（Per User）CAL |
| --- | --- | --- |
| 綁在誰身上 | 每一台連線的電腦 | Active Directory 裡的使用者 |
| 工作群組（無網域）能追蹤嗎 | ✅ 可以，不需要 AD | ❌ 無法追蹤 |
| 會不會強制限制 | 會：沒有可用授權就只能用 90 天臨時授權 | 不會強制，管理者要自己確認數量夠 |
| 臨時授權 | 第一次連線發給，有效 90 天 | 沒有 |
| 可以收回重新分配嗎 | 最多可撤銷 20% | 不能撤銷 |

結論：**工作群組環境請買每裝置 CAL**，授權伺服器才能正確發放與追蹤。

### 3-2 寬限期

部署後有 **120 天**寬限期，期間不需要授權伺服器；到期後，用戶端必須拿到授權伺服器發的有效 CAL 才能登入。

### 3-3 版本要對得上

| 規則 | 說明 |
| --- | --- |
| CAL 版本 ≥ 工作階段主機版本 | 舊版 CAL 不能連新版 Windows Server；新版 CAL 可以連舊版 |
| 授權伺服器版本 ≥ CAL 版本 | CAL 要裝在同版或更新版的授權伺服器上 |

例：Windows Server 2012 的工作階段主機，用 2012 或更新版的 CAL 都可以；但 2012 的 CAL 不能拿去連 2016 的主機。官方文件的對照表只列 2016 以後的版本，2012 的部分是依同一規則推論（**推測**）。

## 4. 常見問題

| 現象 | 怎麼辦 |
| --- | --- |
| 120 天後使用者連不進來 | 寬限期到了：確認授權伺服器已啟用、CAL 已安裝，且群組原則有指定授權伺服器 |
| 授權管理員裡看不到每使用者 CAL 被使用 | 工作群組環境本來就追蹤不到，改用每裝置 CAL |
| 每裝置 CAL 數量不夠 | 用戶端仍可使用 90 天臨時授權，期限到前要補足 |
