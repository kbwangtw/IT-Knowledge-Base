# Windows 2008 格式化 18 TB RAID 5 失敗：配置單位改成 8K 就成功

> **一句話**：12 顆 2 TB 做成 RAID 5 後約 18 TB，用預設 4K 配置單位格式化 NTFS 會失敗（叢集數超過上限）；把配置單位大小改成 **8K** 就能格式化。

| 項目 | 內容 |
| --- | --- |
| 適合誰看 | 格式化超大磁碟時出現「無法完成格式化」或「叢集數目比預期還要多」的人 |
| 環境 | Windows Server 2008 SP2 x64；12 × 2 TB 硬碟，RAID 5 |
| 日期 | 2014-03-19（原文發表於 Blogger，2026-10-24 改寫為新手版） |
| 結論 | ✅ 配置單位 8K 格式化成功 ⚠️ 改成 GPT 無效 |

## 1. 先認識幾個名詞

| 名詞 | 白話解釋 |
| --- | --- |
| **配置單位大小（叢集大小）** | 檔案系統一次分配的最小空間；越大，同樣容量需要的叢集數越少 |
| **叢集數上限** | NTFS 的叢集數有上限；4K 叢集時，單一磁碟區上限約 16 TB |
| **GPT／MBR** | 磁碟分割表格式；超過 2 TB 要用 GPT，但它**不能**解決叢集數的問題 |

## 2. 為什麼會失敗

```text
容量 ÷ 叢集大小 = 需要的叢集數
約 18 TB ÷ 4K  → 超過 NTFS 上限（約 16 TB）→ 格式化失敗
約 18 TB ÷ 8K  → 在上限內（約 32 TB）     → 成功
```

| 叢集大小 | NTFS 單一磁碟區上限（約） |
| --- | --- |
| 4K | 16 TB |
| 8K | 32 TB |
| 16K | 64 TB |
| 64K | 256 TB |

## 3. 原作者試過的方法

| 嘗試 | 結果 |
| --- | --- |
| 磁碟管理 → 用預設值格式化 | ❌「Windows 無法完成格式化」 |
| 把基本磁碟改成 GPT | ❌ 一樣失敗 |
| 配置單位大小改成 **8K** | ✅ 成功 |

![磁碟管理格式化失敗的訊息（原作者截圖）]({{ '/docs/blogger/windows/images/win2008-format-failed.png' | relative_url }})

## 4. 步驟：用 8K 格式化

**怎麼做**：**電腦管理 → 磁碟管理** → 對該磁碟區按右鍵 → **格式化** → 檔案系統 NTFS，**配置單位大小**選 **8192**（8K）→ 確定。

> 原文寫「4096 Bits、8196 Bits」，正確應為 4096 **位元組**（4K）、8192 位元組（8K）。

**應該看到什麼**：格式化完成，磁碟區顯示約 18 TB 可用。

## 5. 常見問題

| 現象 | 怎麼辦 |
| --- | --- |
| 叢集數目比預期還要多 | 配置單位調大，依容量對照第 2 節的表 |
| 超過 2 TB 的磁碟看不到全部空間 | 要用 GPT，不是 MBR |
| 要放大量小檔案 | 叢集越大，小檔案越浪費空間；依用途取捨 |
