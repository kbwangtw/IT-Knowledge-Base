# Nebula 兩層樓 Site-to-Site VPN：6F USG FLEX 100 × 10F USG FLEX 50HP

> **一句話**：6 樓已經有一台 USG FLEX 100（PPPoE 固定 IP），10 樓新增一台 USG FLEX 50HP 和一台 NWA50BE 無線 AP。10F 線路原以為是浮動 IP，經查證是 **PPPoE 固定 IP（6 個）**，設好撥號就能上網。兩台防火牆在 Nebula **同一個組織、各自一個站點**，在「站點-到-站點 VPN」頁面點 **VPN 規劃工具**，Nebula 就自動把兩邊設成「中心和分支」（Hub-and-Spoke，6F 是 Hub、10F 是 Spoke），不用手動填金鑰和對方 IP。互通的只有 6F lan1 和 10F LAN，6F lan2 不加入。

## 1. 先認識幾個名詞

| 名詞 | 白話解釋 |
| --- | --- |
| **Nebula** | Zyxel 的雲端管理平台。設備接上網路後，設定都在網頁上改，設備自己去雲端拿設定 |
| **組織／站點** | Nebula 的兩層分類：組織是「公司」，站點是「一個地點」。**一個站點只能放一台防火牆**，所以本案開了「六樓」「十樓」兩個站點 |
| **ZLD／uOS** | Zyxel 防火牆的兩種韌體。舊款 USG FLEX 100 跑 ZLD；名稱有 H 的新款（例如 USG FLEX 50HP）跑 uOS。兩種在 Nebula 上的畫面不完全一樣 |
| **Site-to-Site VPN（站點-到-站點 VPN）** | 兩個地點的防火牆之間拉一條加密通道，讓兩邊內網像接在同一個網路一樣互通；電腦不用裝任何軟體 |
| **IPsec** | Site-to-Site VPN 最常用的加密協定。Nebula SD-VPN 底層就是 IPsec |
| **Nebula SD-VPN** | Nebula 的「自動 VPN」（舊稱 Nebula VPN）：同一個組織裡的防火牆打開這個功能，Nebula 自動交換金鑰、對方 IP 和網段 |
| **VPN 規劃工具**（VPN orchestrator） | Nebula 一次幫多個站點設定 SD-VPN 的精靈。本案用它自動完成兩邊設定 |
| **VPN 區域** | SD-VPN 的分組，同一個區域內的站點才會互連。本案用「預設值」 |
| **中心和分支**（Hub-and-Spoke） | 像腳踏車輪：Hub 是輪軸（中心），Spoke 是輻條（分點），分點都連到中心。本案 6F 是 Hub、10F 是 Spoke |
| **Split tunnel** | 只有「要去對方內網」的封包走 VPN，上網的流量各自從自己的 WAN 出去 |
| **本地網路／使用 VPN** | 防火牆上每個 LAN 網段旁邊的開關：打開，這個網段才會被放進 VPN、讓對方看得到 |
| **PPPoE** | 用帳號密碼「撥號」上網的方式。中華電信光世代常見，可以搭配固定 IP |
| **WAN／LAN** | 防火牆接網際網路的那一側叫 WAN；接內部電腦的那一側叫 LAN |
| **DHCP Pool／約期** | 防火牆自動發 IP 的範圍；約期是發出去的 IP 可以用多久，到期前電腦會自動續約 |
| **網段重疊** | 兩邊用了同一個網段（例如都是 192.168.1.0/24），防火牆分不出封包該留在本地還是送進 VPN，VPN 會不通 |
| **PoE／PoE+（802.3at）** | 用網路線同時供電。50HP 的 P5 有 PoE；本案 NWA50BE 現場無法用 PoE 供電，改用變壓器 |
| **MTU／MSS** | 一個封包最大能多大。PPPoE 和 IPsec 都會吃掉封包空間，太大的封包可能被丟掉 |

## 3. 規劃確認結果

| 問題 | 結果 | 對設定的影響 |
| --- | --- | --- |
| 6F 機型 | ✅ **USG FLEX 100**（ZLD，非 H 系列） | 和 10F 的 50HP（uOS）是不同韌體。Zyxel 官方 FAQ 的做法是 **Hub-and-Spoke，H 系列當 Spoke**；VPN 規劃工具建出來的結果也一樣（6F Hub、10F Spoke） |
| 6F lan2 加入 VPN？ | ✅ **不要** | 6F 的 lan2「使用 VPN」為關，10F 連不到 192.168.200.x |
| AP 型號 | ✅ **NWA50BE** | Wi-Fi 7、**雙頻**（2.4 GHz＋5 GHz，**沒有 6 GHz**）、2.5G 網路埠、典型耗電約 16 W |
| 10F 規模 | ✅ **1 人、3 台設備** | DHCP Pool 不需放大 |
| 10F 的 WAN | ✅ **PPPoE 固定 IP（6 個）** | 原本得知是浮動 IP，經查證為固定 IP。兩邊都是固定 IP，VPN 不必依賴 DDNS，最穩定 |
| AP 供電 | ✅ **變壓器** | 50HP 的 PoE 埠是 P5，但 NWA50BE 無法由 50HP 的 P5 供電，改用變壓器（經銷商規格標示支援 PoE+，與現場結果不一致，原因未確認）。AP 網路線接 P2～P5 任一埠即可 |

> **為什麼「查證線路型態」很重要**：中華電信 PPPoE 帳號的後綴決定拿到哪種 IP。固定 IP 用 `<HiNet 帳號>@ip.hinet.net`，浮動 IP 用 `<HiNet 帳號>@hinet.net`。如果照「浮動 IP」的資訊填成 `@hinet.net`，雖然可能撥得通，但拿到的不是申請的固定 IP。

## 4. 步驟一：在 Nebula 建立 10F 站點並註冊設備

**做什麼**：10F 需要自己的站點，因為一個站點只能有一台防火牆。

**怎麼做**：

1. 在 6F（站點「六樓」）所在的**同一個組織**底下新增站點，本案命名為「十樓」
2. 在「十樓」站點註冊兩台設備（USG FLEX 50HP、NWA50BE），需要機身上的 **MAC 位址** 和 **序號（S/N）**
3. 設備上線後，建議兩台防火牆都升到最新韌體（社群回報過 H 系列和舊款 USG FLEX 之間的 SD-VPN 問題是韌體 bug，見第 10 節）

**應該看到什麼**：畫面上方「站點」下拉選單可以切換「六樓」「十樓」，十樓的設備清單出現兩台設備。

> **注意**：不要把 10F 的防火牆加到 6F 的站點；兩個站點也必須在同一個組織，SD-VPN 才能自動互連。

## 5. 步驟二：設定 10F 防火牆的 WAN（PPPoE 固定 IP）

**做什麼**：先讓 50HP 自己撥號上網、在 Nebula 上線，再做 VPN。

### 5-1 埠的分配

| 實體埠 | 介面 | 說明 |
| --- | --- | --- |
| P1 | ge1（WAN） | 接中華電信光纖數據機 |
| P2～P5 | ge3（LAN） | 接電腦、AP |
| P5 | ge3（有 PoE） | 可供電給 PoE 設備；本案 NWA50BE **不靠 P5 供電**，用變壓器 |

### 5-2 新增 PPPoE（50HP 本機網頁介面）

**怎麼做**：50HP 還沒上網前連不到 Nebula，所以先登入 50HP 的本機網頁介面，在 WAN 介面「新增 PPPoE」：

| 欄位 | 填法 | 說明 |
| --- | --- | --- |
| 認證方式 | PAP（預設已勾選）；撥不通時改「全選」 | 「全選」會讓防火牆和中華電信自動協商 CHAP／PAP |
| 使用者名稱 | `<HiNet 帳號>@ip.hinet.net` | **固定 IP 用 `@ip.hinet.net`**，帳號在中華電信開通通知單上；欄位上限 64 字元 |
| 密碼／確認密碼 | HiNet 上網密碼 | **不要寫進文件、不要拍照外流** |
| 服務名稱 | 留空 | 中華電信不需要 |
| 壓縮 | 預設「開」 | 撥號失敗時可改「關」再試 |
| 閒置等候時間 | **0** | 0＝永遠連線。不是 0 的話，沒流量時會斷線，VPN 也跟著斷 |
| IP 位址、預設閘道 | 留空 | 撥號成功後會自動拿到固定 IP（推測；本案是否手動填寫未記錄） |

套用到 P1（ge1）。

**應該看到什麼**：WAN 狀態顯示 PPPoE 已連線，IP 為中華電信給的固定 IP（不是 192.168.x、10.x 開頭）；Nebula 上 50HP 變成上線。✅ 本案實測：設好後即可上網。

> **本機改完，Nebula 也要一致**：50HP 交給 Nebula 管理後，雲端設定會蓋過本機設定。請確認 Nebula「十樓」站點的 WAN 也是同一組 PPPoE 設定、閒置時間 0，否則套用時可能斷線。

### 5-3 LAN 與 DHCP

本案實際 LAN（ge3）的 IP 是 **192.168.10.254/24**，和原規劃的 192.168.10.1 不同。兩者都能用，但 DHCP 發給電腦的「預設閘道」必須也是 192.168.10.254。10F 電腦已能 ping 到 6F，推測閘道設定正確；Pool、DNS、約期仍待確認。

| 欄位 | 原規劃 | 實際 |
| --- | --- | --- |
| IP 位址 | 192.168.10.1 | **192.168.10.254** |
| 子網路遮罩 | 255.255.255.0（/24） | /24 ✅ |
| DHCP Pool | 192.168.10.10～50 | ⏳ 待確認 |
| DNS | 8.8.4.4、101.101.101.101 | ⏳ 待確認 |
| 約期 | 2 天 | ⏳ 待確認 |

**應該看到什麼**：10F 電腦拿到 192.168.10.x 的 IP，`ipconfig` 顯示預設閘道 192.168.10.254，可以開網頁。

## 6. 步驟三：用 VPN 規劃工具建立 SD-VPN

**做什麼**：讓 Nebula 一次把兩個站點的 SD-VPN 設好，而不是兩邊各自手動設定。

**怎麼做**：

1. 進任一站點 → 左側「設定」→「站點-到-站點 VPN」
2. 頁面最下方有一行「設定多個站點的 VPN 很麻煩。使用 **VPN 規劃工具** 以節省您的時間」，點「VPN 規劃工具」
3. 依精靈把「六樓」「十樓」放進同一個 VPN 區域、選「中心和分支」，六樓當 Hub
4. 完成後，回兩個站點的「站點-到-站點 VPN」頁面確認結果（6-1、6-2）

> **為什麼是「中心和分支」**：只有兩個站點時，兩種拓撲效果一樣；Zyxel 官方 FAQ 對「H 系列配舊款 USG FLEX」的建議就是 Hub-and-Spoke、H 系列當 Spoke，VPN 規劃工具建出來的結果也符合這個建議。

### 6-1 六樓（Hub）的實際設定

| 欄位 | 設定值 |
| --- | --- |
| 主介面 | wan1 |
| 二級介面 | 無 |
| 本地網路：lan1（192.168.0.0/24） | 使用 VPN：**開** |
| 本地網路：lan2（192.168.200.0/24） | 使用 VPN：**關** |
| SD-VPN 啟用 | 開 |
| VPN 區域 | 預設值 |
| VPN 拓撲圖 | Split tunnel（只有 site-to-site 封包通過 VPN）；中心和分支 |
| Hubs（對點連接至） | 1. 六樓 |

### 6-2 十樓（Spoke）的實際設定

H 系列的頁面分成「Nebula SD-VPN」和「手動連接VPN」兩個分頁，以下是「Nebula SD-VPN」分頁：

| 欄位 | 設定值 |
| --- | --- |
| 主介面 | ge1 |
| 二級介面 | 無 |
| 本地網路：ge3（192.168.10.254/24） | 使用 VPN：**開** |
| 啟用 | 開 |
| VPN 區域 | 預設值 |
| VPN 拓撲圖 | Split tunnel（只有 site-to-site 封包通過 VPN）；中心與分支 |
| Hubs（對點連接至） | 1. 六樓 |

> **兩邊畫面的小差異**：6F（ZLD）的本地網路顯示「網段」（192.168.0.0/24），10F（uOS）顯示「介面 IP」（192.168.10.254/24），代表的都是整個 /24 網段（推測是兩種韌體的顯示方式不同）。六樓自己的 Hubs 也列出「六樓」，表示它就是 Hub。

**應該看到什麼**：兩邊設定如上表；儲存後約 1～2 分鐘生效（頁面底部提示）。

## 7. 備案：手動 IPsec（只在 SD-VPN 建不起來時用）

社群有回報過 H 系列和舊款 USG FLEX 之間 SD-VPN 建不起來、改用手動 IPsec 就通的案例。本案兩邊都是固定 IP，手動設定也很單純。10F 在「手動連接VPN」分頁、6F 在對應的非 Nebula 對點設定新增對方：

| 欄位 | 6F 這邊填 | 10F 這邊填 |
| --- | --- | --- |
| 對方公網 IP | `<10F 固定 IP>` | `<6F 固定 IP>` |
| 對方網段 | 192.168.10.0/24 | 192.168.0.0/24 |
| 預先共用金鑰 | 兩邊填同一組長字串，**不要寫進文件** | 同左 |
| IKE 版本、加密演算法 | 兩邊必須完全相同，例如 IKEv2、AES256、SHA256 | 同左 |

> 本案用 VPN 規劃工具已建立完成，目前不需要這個備案。

## 8. 步驟四：設定 10F 的 NWA50BE 與 SSID

**做什麼**：讓 10F 的無線設備也在 192.168.10.x，自然就能走 VPN 連到 6F。

**怎麼做**：

1. NWA50BE 接**變壓器**供電，網路線接 50HP 的 P2～P5 任一埠，AP 會從 ge3 拿到 192.168.10.x 的管理 IP
   - 現場確認 NWA50BE 無法由 50HP 的 P5 供電，改用變壓器（經銷商規格標示支援 PoE+，與現場結果不一致，原因未確認）
2. 切到「十樓」站點 → 設定 → 無線 AP 的 SSID 設定，新增 SSID：

| 欄位 | 填法 |
| --- | --- |
| SSID 名稱 | `<10F SSID>` |
| 安全性 | WPA2/WPA3 Personal（混合模式，舊裝置用 WPA2、新裝置用 WPA3） |
| VLAN | 不設（Untagged），直接走 ge3 |
| 頻段 | 2.4 GHz＋5 GHz（NWA50BE 是雙頻，沒有 6 GHz） |

**應該看到什麼**：手機連上 `<10F SSID>`，拿到 192.168.10.x 的 IP，可以上網。

> 本案 AP 和有線電腦在同一個網段，最簡單。若之後要做訪客 Wi-Fi，建議另開一個 VLAN 網段並**不要**加入 VPN，做法可參考[圖書館 Nebula 網路改造](../zyxel-nebula-library-vlan-dual-wan-plan/)。

## 9. 步驟五：驗收

**做什麼**：從兩邊互相連線，證明通道真的通，而不是只有設定畫面看起來對。

### 9-1 看 Nebula 狀態

兩個站點都到「監控」→ 防火牆的 VPN 連線狀態頁面（名稱依版本可能不同）：

**應該看到什麼**：對方站點狀態為已連線，對方網段顯示 192.168.0.0/24（在 10F 看）或 192.168.10.0/24（在 6F 看）；6F 這邊**不應該**出現 192.168.200.0/24。

也可以登入 50HP 的本機網頁介面，在 VPN Status → IPsec VPN → Site to Site VPN 確認 SD-VPN 已連線（Zyxel 官方 FAQ 的路徑）。

### 9-2 從 10F 電腦測試

```text
ping 192.168.0.1
tracert 192.168.0.1
```

| 片段 | 意思 |
| --- | --- |
| `ping 192.168.0.1` | 對 6F 的閘道送測試封包，有回應代表封包能過去也能回來 |
| `tracert 192.168.0.1` | Windows 的路徑追蹤，看封包經過哪些設備 |

**應該看到什麼**：

- `ping` 有回應，時間通常在幾毫秒到幾十毫秒（依兩邊線路而定）
- `tracert` 第一跳是 192.168.10.254（10F 閘道），第二跳就到 192.168.0.1：中間沒有出現 ISP 的路由器，代表封包走的是 VPN 通道

### 9-3 測真正要用的服務

| 測試 | 怎麼做 | 應該看到什麼 |
| --- | --- | --- |
| 檔案分享 | 10F 電腦開檔案總管，輸入 `\\192.168.0.<6F 檔案主機>` | 跳出登入視窗或直接看到共用資料夾 |
| 印表機 | 10F 電腦新增 6F 的網路印表機（用 IP） | 可以印出測試頁 |
| 反方向 | 從 6F 電腦 ping 192.168.10.254 或 10F 的電腦 | 有回應 |
| lan2 隔離 | 從 10F ping 192.168.200.1 | **沒有回應**才是對的 |
| 上網不走 VPN | 10F 電腦查外網 IP（例如開「我的 IP」查詢網站） | 顯示 `<10F 固定 IP>`，不是 6F 的 IP（Split tunnel） |

## 10. 常見問題

| 現象 | 怎麼辦 |
| --- | --- |
| PPPoE 撥不通 | 1. 帳號後綴：固定 IP 用 `@ip.hinet.net`、浮動 IP 用 `@hinet.net`；2. 認證方式改「全選」；3. 確認光纖數據機是橋接、沒有自己撥號 |
| PPPoE 撥通了，但 IP 不是申請的固定 IP | 帳號後綴填成 `@hinet.net`，改成 `@ip.hinet.net` 重撥 |
| 本機設好 PPPoE，交給 Nebula 後斷線 | Nebula 的 WAN 設定蓋過本機設定。到 Nebula 該站點把 WAN 設成同一組 PPPoE |
| Nebula 一直顯示 VPN 未連線 | 1. 兩個站點在不在**同一個組織**、同一個 VPN 區域；2. 兩邊 SD-VPN 都啟用，拓撲為中心和分支、Hub 是六樓；3. 10F 的 WAN 是不是公網 IP |
| 設定都對，VPN 還是建不起來，log 一直出現 `try to nail up` | 社群回報過 H 系列 VPN 的 DDNS 不更新、導致 SD-VPN 建不起來的韌體 bug（Zyxel 承認並私下提供修正）。先升級兩台防火牆韌體；仍不行就聯絡 Zyxel 客服，或改用第 7 節的手動 IPsec |
| 通道顯示已連線，但 ping 對方閘道不通 | 社群回報過 H 系列 WAN 在 192.168.1.0/24（接在家用型路由器後面）時，通道建立卻不通的案例。避免讓 50HP 接在其他路由器後面 |
| 閘道通、對方電腦不通 | 多半是 **Windows 防火牆預設擋 ping**，不是 VPN 的問題；改用檔案分享或印表機測試 |
| 10F 電腦能上網，但 ping 不到自己的閘道 192.168.10.1 | 本案 10F 閘道是 **192.168.10.254**，不是 .1 |
| ping 得通，但大檔案傳一半卡住、某些網頁打不開 | PPPoE 加 IPsec 讓封包可用空間變小（推測 MTU／MSS 問題）。在防火牆的 VPN 或介面設定裡調整 TCP MSS（例如 1350），再測一次 |
| 10F ping 得到 6F lan2 | 6F 的 lan2「使用 VPN」應為關，回 6-1 檢查 |
| 以後員工在家用 Remote Access VPN 連回 6F 不通 | 家用路由器常用 192.168.0.0/24 或 192.168.1.0/24，和 6F lan1 **重疊**。這是既有網段的潛在風險，若之後要開放遠端連線，需評估是否調整網段 |
| NWA50BE 插 50HP 的 P5 不開機 | 本案現場就是這個狀況，改用變壓器供電即可。經銷商規格標示支援 PoE+，與現場結果不一致，原因未確認（推測可能是 P5 供電或協商問題）；若想改回 PoE，可詢問 Zyxel 客服 |
| 手機看不到 6 GHz | NWA50BE 是雙頻機種，本來就沒有 6 GHz |
| 英文教學和中文介面對不起來 | 對照：Site-to-Site VPN＝站點-到-站點 VPN；Nebula VPN＝Nebula SD-VPN；Hub-and-Spoke＝中心和分支；VPN orchestrator＝VPN 規劃工具；Local networks／Use VPN＝本地網路／使用 VPN；Outgoing interface＝主介面 |
