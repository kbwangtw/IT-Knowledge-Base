# 有用中華電信資安艦隊：DNS 為什麼不能設 8.8.8.8？

> **一句話**：線路有申請中華電信「資安艦隊」時，DNS 一定要設成中華電信的 `210.69.1.1`；設成 `8.8.8.8` 這類公共 DNS 會「網路通、但網址打不開」。

| 項目 | 內容 |
| --- | --- |
| 適合誰看 | 遇到「ping 得到、網頁卻打不開」的人；負責設定客戶端網路的人 |
| 適用情境 | 客戶線路啟用中華電信資安艦隊（防色情、防毒、防駭） |
| 正確設定 | DNS 指定 `210.69.1.1`（目前已知只有這一組） |
| 驗證程度 | 2026-10-07 客戶現場確認：一般公共 DNS 無法解析，指定 `210.69.1.1` 才能解析；中華電信機房端**怎麼過濾**沒有向原廠確認，下文原因是依現象推論 |

## 1. 先認識幾個名詞

| 名詞 | 白話解釋 |
| --- | --- |
| **DNS** | 網路的「電話簿」：把 `www.google.com` 這種名稱換成 IP 位址。DNS 壞了，網址就打不開，但直接用 IP 仍然通 |
| **公共 DNS** | 任何人都能用的 DNS，例如 Google 的 `8.8.8.8`、`8.8.4.4` |
| **資安艦隊** | 中華電信的加值服務，在機房端用 DNS 過濾惡意或不當網站 |
| **ping（ICMP）** | 測試「線路通不通」的工具，和 DNS 走的是不同管道 |
| **轉寄站（Forwarder）** | 公司內部 DNS 查不到時，代為轉問外部的那台 DNS |

## 2. 為什麼 ping 得到，網址卻打不開？

`ping` 用的是 ICMP，DNS 查詢用的是 UDP／TCP 53 埠，兩者走不同的路：

| 測試 | 協定 | 在資安艦隊下的結果 |
| --- | --- | --- |
| `ping 8.8.8.8` | ICMP | ✅ 通 |
| `nslookup example.com 8.8.8.8` | DNS（53 埠） | ❌ 逾時或失敗 |
| `nslookup example.com 210.69.1.1` | DNS（53 埠） | ✅ 正常回應 |

資安艦隊的過濾做在 **DNS 這一層**：你查網址時，由中華電信的 DNS 決定要不要放行。如果直接去問外部 DNS，就等於繞過過濾，所以機房端會擋掉這類查詢。結果就是「**線路是通的，名稱解析是斷的**」。

> ⚠️ 最容易誤判的地方：看到 `ping 8.8.8.8` 通，就以為網路沒問題。其實網路沒斷，是 DNS 查詢被擋了。

## 3. 現場怎麼確認

**Windows：**

```powershell
ping 8.8.8.8
nslookup www.google.com 8.8.8.8
nslookup www.google.com 210.69.1.1
ipconfig /all
```

**Linux：**

```bash
ping -c 3 8.8.8.8
dig @8.8.8.8 www.google.com
dig @210.69.1.1 www.google.com
cat /etc/resolv.conf
```

**怎麼判讀：**

| 結果 | 意思 | 下一步 |
| --- | --- | --- |
| `ping 8.8.8.8` 通 | 對外線路正常 | 繼續看 DNS |
| 問 `8.8.8.8` 失敗、問 `210.69.1.1` 成功 | **就是本篇的情況** | 照第 4 節改 DNS |
| 兩個都失敗 | 不是本篇問題 | 往防火牆、Gateway 或線路查 |

## 4. 要改哪些地方

不只電腦網卡，**所有會對外查 DNS 的設備**都要檢查：

| 位置 | 要確認的設定 |
| --- | --- |
| 電腦、伺服器的網卡（手動設定 IP 的） | 「慣用 DNS」和「其他 DNS」都不能填公共 DNS |
| DHCP 伺服器（路由器、防火牆、Windows DHCP） | 發給用戶端的 DNS 選項 |
| AD DNS／內部 DNS 的轉寄站 | 轉寄目標改成 `210.69.1.1` |
| 防火牆、路由器本身 | 設備自己用的 DNS（更新、NTP、VPN 會用到） |
| NAS、印表機、IP Cam、Wi-Fi AP | 手動設定的 DNS |

**有 AD 網域的環境**：用戶端繼續指向**內部 DNS**，只把內部 DNS 的**轉寄站**改成 `210.69.1.1`。不要讓用戶端直接指外部 DNS，否則 AD 網域名稱會解析不到。

## 5. 容易漏掉的地方

| 盲點 | 說明 |
| --- | --- |
| 「其他 DNS」填了 8.8.8.8 | 很多人習慣備援填 `8.8.8.8`，但它一樣無法解析。主 DNS 一慢就切過去，造成**時好時壞**。目前只有一組，「其他 DNS」留空即可 |
| 設備上寫死的設定 | 很多設備被手動寫死 `8.8.8.8`，申請資安艦隊後要逐台清查，不是只改 DHCP |
| 瀏覽器的「安全 DNS」（DoH） | Chrome、Edge、Firefox 開啟後可能不走系統 DNS。會不會被擋、會不會繞過過濾，**這次沒有實測**；遇到「系統 DNS 正常、某個瀏覽器怪怪的」時先檢查這個 |
| 只有一組 DNS = 單點故障 | `210.69.1.1` 出狀況時，全公司都解析不了網址。有內部 DNS（AD DNS 或防火牆的 DNS Proxy）的話，讓用戶端都問內部 DNS、再轉寄到 `210.69.1.1`，內部快取能緩衝短暫中斷 |
| 退租資安艦隊後 | 評估是否改回原本的 DNS，並記錄異動 |

遇到全公司「網路通、網址打不開」時，先測 `nslookup www.google.com 210.69.1.1`，再找中華電信。
