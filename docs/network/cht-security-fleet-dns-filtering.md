# 有用中華電信資安艦隊：DNS 為什麼不能設 8.8.8.8？

客戶如果向中華電信申請「資安艦隊」的防色情、防毒、防駭服務，中華電信機房端會做 DNS 過濾。這時候用戶端的 DNS **不能設定一般常用的 DNS**（例如 Google 的 `8.8.8.8`、`8.8.4.4`），**一定要指定中華電信的 DNS 伺服器 `210.69.1.1`**，才能正常解析網址。

**現象最容易誤判：`ping 8.8.8.8` 是通的，但網址解析不出來。網路沒斷，是 DNS 查詢被擋。**

> 紀錄日期：2026-10-07。來源：客戶現場維運經驗。「只有指定 `210.69.1.1` 才能解析」已於現場確認；中華電信端的實際過濾方式（攔截、丟棄或改寫 DNS 封包）沒有向原廠確認，下文的原因說明是依現象推論。

## 結果先看

| 項目 | 說明 |
| --- | --- |
| 適用情境 | 客戶線路有啟用中華電信資安艦隊（防色情、防毒、防駭） |
| 錯誤設定 | DNS 指向一般常用的公共 DNS，例如 `8.8.8.8`、`8.8.4.4` |
| 正確設定 | DNS 一定要指定中華電信 DNS `210.69.1.1` |
| 典型症狀 | `ping 8.8.8.8` 有回應；`nslookup`、瀏覽器開網址失敗 |
| 驗證狀態 | 已確認：一般常用 DNS 無法解析，指定 `210.69.1.1` 才能解析；機房端過濾機制未向中華電信確認 |

## 1. 為什麼 ping 得到，卻解析不了？

`ping` 用的是 ICMP，DNS 查詢用的是 UDP／TCP 53 port。兩者走的是不同的路：

| 測試 | 協定 | 資安艦隊下的結果 |
| --- | --- | --- |
| `ping 8.8.8.8` | ICMP | 通 |
| `nslookup example.com 8.8.8.8` | DNS（UDP／TCP 53） | 逾時或失敗 |
| `nslookup example.com 210.69.1.1` | DNS（UDP／TCP 53） | 正常回應 |

資安艦隊的過濾是在 DNS 層做的：使用者查詢網域時，由中華電信的 DNS 判斷要不要放行。若用戶端直接問外部 DNS，等於繞過過濾，所以機房端會擋掉這類查詢。結果就是「IP 層是通的，名稱解析是斷的」。

## 2. 現場怎麼確認

在 Windows 用戶端執行：

~~~powershell
ping 8.8.8.8
nslookup www.google.com 8.8.8.8
nslookup www.google.com 210.69.1.1
ipconfig /all
~~~

Linux：

~~~bash
ping -c 3 8.8.8.8
dig @8.8.8.8 www.google.com
dig @210.69.1.1 www.google.com
cat /etc/resolv.conf
~~~

判讀方式：

1. `ping 8.8.8.8` 通 → 對外線路正常。
2. 問 `8.8.8.8` 失敗、問 `210.69.1.1` 成功 → 符合本篇情境，改 DNS 設定即可。
3. 兩個都失敗 → 不是本篇問題，往防火牆、Gateway 或線路查。

## 3. 要改哪些地方

不只用戶端網卡，所有「會往外問 DNS」的設備都要檢查：

| 位置 | 要確認的設定 |
| --- | --- |
| 用戶端網卡（手動設定 IP 的電腦、伺服器） | 慣用／其他 DNS 都不可設一般常用 DNS（`8.8.8.8`、`8.8.4.4` 等） |
| DHCP Server（路由器、防火牆、Windows DHCP） | 發給用戶端的 DNS 選項 |
| AD DNS／內部 DNS 的轉寄站（Forwarder） | 轉寄目標改成 `210.69.1.1` |
| 防火牆、路由器本身的 DNS | 設備自己查詢（更新、NTP 網域、VPN）用的 DNS |
| NAS、印表機、IP Cam、Wi-Fi AP 等設備 | 手動設定的 DNS |

有內部 AD DNS 的環境，用戶端應該繼續指向內部 DNS，只把內部 DNS 的轉寄站改成 `210.69.1.1`，不要讓用戶端直接指外部 DNS，否則 AD 網域解析會壞掉。

## 4. 容易漏掉的地方

- **瀏覽器的 DNS over HTTPS（DoH）**：Chrome、Edge、Firefox 開啟「安全 DNS」後，可能不走系統 DNS。是否會被資安艦隊擋掉、或繞過過濾，這次沒有實測；遇到「系統 DNS 正常、某個瀏覽器怪怪的」時，可先檢查這個設定。
- **「其他 DNS」欄位也不能填一般常用 DNS**：很多人習慣主要填 `210.69.1.1`、備援填 `8.8.8.8`。備援的那組一樣無法解析，主 DNS 一慢就切過去，會造成時好時壞。
- **既有設備的硬寫設定**：很多人習慣把 `8.8.8.8` 寫死在設備上，申請資安艦隊後要逐台清查，不是只改 DHCP。
- **退租資安艦隊後**：要評估是否改回原本的 DNS 設定，並記錄異動。
