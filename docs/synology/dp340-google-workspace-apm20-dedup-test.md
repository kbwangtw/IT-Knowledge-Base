# DP340 顯示省下 75% 空間，該怎麼看？

> **一句話**：DP340 的報表說「省下 75% 空間」，這是 6 台虛擬機加上 Google Workspace **合併計算**的結果；這篇教你怎麼讀懂這個數字，以及它**不能**證明什麼。

| 項目 | 內容 |
| --- | --- |
| 適合誰看 | 第一次看到備份設備「重複資料刪除率」報表的人 |
| 設備 | Synology DP340（Active Protect Manager，APM） |
| 資料來源 | 2026-09-11 整理的一張報表截圖（截圖實際擷取時間待補） |
| 結論 | 75% 是當下這組合併資料的容量關係，**不是**固定承諾，也不代表每個服務都備份成功 |

## 1. 先認識幾個名詞

| 名詞 | 白話解釋 |
| --- | --- |
| **重複資料刪除（Deduplication）** | 備份時發現兩份資料內容一樣，就只存一份、另一份記個「指標」，藉此省空間 |
| **邏輯用量** | 如果不做任何節省，這些備份「原本」要佔多少空間 |
| **實體用量** | 實際寫在硬碟上的大小 |
| **減省量** | 邏輯用量 − 實體用量，也就是省下來的空間 |
| **資料節省率（例如 3.96x）** | 邏輯用量是實體用量的幾倍；**不是**「省了 396%」 |
| **Guest OS** | 虛擬機裡跑的作業系統，這裡指被備份的 6 台虛擬機 |

## 2. 這次備份了什麼？

- 6 台 Guest OS（虛擬機）
- 約 10 個 Google Workspace 帳號：郵件、行事曆、聯絡人、My Drive
- 1 個 Shared Drive

這些資料**混在一起統計**，沒有分開的數字，所以看不出哪一類貢獻最多節省空間。

> 工作負載的說明來自案例提供的資訊；截圖本身沒有完整顯示機型、日期與篩選條件。

## 3. 原始畫面怎麼讀

![6 台 Guest OS + Google Workspace 合併備份的 APM 重複資料刪除率面板：75%，實體 111.8 GB、減省 330.4 GB、邏輯 442.2 GB，資料節省率 3.96x]({{ '/docs/synology/images/dp340-google-workspace-apm20-dedup-test.png' | relative_url }})

| 面板項目 | 本次顯示 | 意思 |
| --- | --- | --- |
| 邏輯用量 | 442.2 GB | 面板計入的原始資料總量 |
| 實體用量 | 111.8 GB | 實際佔用的資料量 |
| 減省量 | 330.4 GB | 兩者的差額 |
| 重複資料刪除率 | 75% | 省下的比例（四捨五入成整數） |
| 資料節省率 | 3.96x | 邏輯量約是實體量的 3.96 倍 |

這些都沿用面板的名稱與單位，**不是**包含所有系統開銷的整台設備容量。

## 4. 自己用算式核對一次

```text
442.2 − 111.8 = 330.4 GB              ← 減省量
330.4 ÷ 442.2 × 100 ≈ 74.72%  → 面板四捨五入顯示 75%
111.8 ÷ 442.2 × 100 ≈ 25.28%  → 實際只佔原本的約四分之一
442.2 ÷ 111.8 ≈ 3.9553        → 顯示 3.96x
```

算得出來，就代表你真的讀懂了報表。

> ⚠️ **3.96x 不是省下 396%，也不是備份速度快 3.96 倍。**

## 5. 這張圖能證明什麼、不能證明什麼

| ✅ 能證明 | ❌ 不能證明 |
| --- | --- |
| 截圖當下，這組資料的邏輯量與實體量關係 | 未來一年的容量、每日成長量 |
| — | 備份速度或還原時間 |
| — | 每個服務都備份成功 |
| — | 之後還會維持 75% |

- 測試跑了幾天，不等於已有「每日趨勢」。檔案內容、版本數、保留政策和工作負載改變，比例都會跟著變。
- **空間數字好看，不代表備份成功。** 另一篇 Google Workspace 紀錄中，Drive 還原已測過，但 Gmail 備份曾失敗、尚未結案；這張合併容量圖不能推翻那個狀態。

## 6. 下次要一起記錄什麼

| 項目 | 為什麼需要 |
| --- | --- |
| 擷取日期與篩選範圍 | 才知道是不是在比較同一組資料 |
| APM 版本、工作數與服務種類 | 區分版本和工作負載的影響 |
| 備份份數與保留政策 | 解釋容量為什麼累積 |
| 每日的邏輯量、實體量、減省量 | 看成長趨勢，而不是單一時間點 |
| 各服務最後的工作結果 | 避免把容量數字當成成功率 |
| 抽樣還原與資料比對 | 確認省下空間後，資料仍然取得回來 |
